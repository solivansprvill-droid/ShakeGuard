The Problem

你不是不小心，是被精心设计了

「摇一摇」本质是一个把手机晃动映射成点击的传感器监听。它的转化率高得离谱，因为用户几乎是无法避免地会晃到手机。

📳

走路、上车都会触发

只要有连续晃动，加速度阈值就会被突破。你不是在「摇」，你只是在移动。

🎯

放在加载完成的瞬间

页面刚打开、手指还没落稳时最容易晃动，这时弹跳转的成功率最高。

🚪

退出成本被拉高

跳转后返回键常常无法一键回到原页面，多看一个广告就是多一份曝光收益。

⚖️
工信部已多次针对「摇一摇」乱跳转开展整治，要求触发阈值不得过低、必须提供明显关闭方式。但只要技术入口还在，主动权就依然在 App 手里。ShakeGuard 的思路是：不去争论阈值，直接把传感器关掉。
How it works

iOS 与 Android，两条不同的路

iOS 27.2 把这件事做成了系统级隐私开关；安卓不能照抄，但有一个等效的系统入口。

🍎 iOS 27.2 Restrict Motion Data

iOS 把加速度计、陀螺仪封装在 CoreMotion 框架后面，App 想读取运动数据必须通过「运动与健身」隐私授权。

新版系统在 设置 → 隐私与安全性 提供了按 App 的限制开关：被限制的 App 调用 startAccelerometerUpdates() 时收不到任何回调，摇一摇检测直接失效。

👉 优点：粒度精确到单个 App，其他 App 不受影响。

🤖 Android ShakeGuard 方案

安卓读取加速度计不需要任何运行时权限，所以系统层面没有「按 App 拒绝」这种机制（除非 root 后挂 Xposed 模块）。

但系统内置了一个开发者级总开关 Settings.Secure「sensors_off」：置 1 之后全机传感器静默，所有 App 都拿不到运动数据。

👉 取舍：力度更狠，但影响全机 —— 自动横屏、计步、指南针会同时失效，所以我们做了定时自动恢复和一键磁贴，用完就开回来。

Get started

三步开始使用

唯一需要的「门槛」是首次用电脑授权一次系统设置写入权限 —— 之后永久生效，不用再连电脑。

构建并安装 APK

克隆仓库，用 Android Studio 打开（Build → Build APK(s)），把 app-debug.apk 装到手机上。

执行一次授权命令

手机开启 USB 调试并连电脑，执行下面这条命令（App 内也有一键复制按钮）：

adb shell pm grant com.victory.shakeguard android.permission.WRITE_SECURE_SETTINGS

把它放到快捷面板

下拉通知栏 → 编辑磁贴 → 把「传感器开关」拖上去。之后每次打开购物 App 前点一下，退出后点回来。

FAQ

常见问题

能像 iOS 那样只屏蔽某个 App 吗？

不能。安卓的 sensors_off 是全局开关，无法按 App 精确屏蔽 —— 那需要 root 后安装 Xposed / LSPosed 模块，成本和风险都高得多。ShakeGuard 选择的是「一键全局 + 定时自动恢复」这个工程折中。

关闭传感器有什么副作用？

自动旋转屏幕、计步、抬手亮屏、指南针、部分导航的转向判断会暂时失效（GPS 定位本身不受影响）。这也是我们做「定时自动恢复」的原因：设好 5 分钟，忘了也不会一直关着。

需要 root 吗？会收集我的数据吗？

不需要 root。授权用的是 Android 官方的 WRITE_SECURE_SETTINGS 权限，由你自己通过 adb 授予。App 没有申请网络权限，不联网、不上传任何数据。

为什么还要用电脑执行 adb 命令？

安卓出于安全考虑不允许普通 App 修改系统设置（否则任何 App 都能改你的系统状态）。这条命令相当于你亲手把这项能力交给它。授权一次后永久有效，手机重启、换 WiFi 都不需要重做。

会有「传感器关闭」的提示吗？

部分机型状态栏会出现传感器停用的指示。如果你在意，可以用定时恢复让它自动消失。
